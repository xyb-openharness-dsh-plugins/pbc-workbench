# 项目规格 · 小管宝 DuctPal（原发性胆汁性胆管炎 PBC）v0.1

状态：草案（M1 产出，待 G1 签认）。确认人/日期：待签认。
本仓是 **R2 非肿瘤慢性病形态**（确诊档案 + 功能与日常 + 并发症筛查 + 医保与资源），不是肿瘤治疗线形态。

## 1. 问题、用户与最小闭环

- **用户**：已确诊 PBC 的成人患者本人；照护者可选（不设独立代记身份，见 §5 不做）。
- **真实处境**：本病多为长期单一用药（UDCA）+ 3–6 个月一次生化复查；患者手里只有一堆化验单照片，
  说不清「现在算不算控制住」「这次的 ALP 比上次好还是差」「痒和累要不要说」。医生只有 8 分钟。
- **最小闭环**：导入/录入一次化验 → 看到 ALP/GGT/TBil 等按这张单子自带参考上限的对照 →
  同一天记下痒与累 → 复诊前生成「带给医生的 5 个问题 + 最近两次化验」快照并导出。
- **成功标准**：患者能在 3 分钟内完成"一次化验 + 一次感受记录"，并在复诊前导出含来源与日期的快照。

## 2. 方案与 ADR

| 决策 | 选项 | 选择与理由 |
| --- | --- | --- |
| A1 布局 | 业务整页 customFrame / 标准分栏 | **customFrame**：家族统一形态，AI 面板在右 65/35 可拖可收；业务区不依赖会话 |
| A2 数据 | 纯 JSON / SQLite + 读模型 | **SQLite**（schema 冻结 + 迁移只增），事实层与候选层分表；导出用快照读模型 |
| A3 症状面 | 并入指标页 / 独立功能线 | **独立一级「痒与累」**：PBC 的瘙痒与乏力没有客观指标可替代，塞进指标页会被读成"附带备注" |
| A4 指南层 | 全量接入 G1–G3 / 只做 CTCAE 对照 | **只做 CTCAE 对照**：中文指南原件本轮未取得（见 GUIDELINE-BRIDGE），不虚构页码 |

## 3. 功能范围（9 一级 / 30 二级）

详见 `docs/DIFF-MATRIX.md`（功能线走查）与 `docs/INTERACTION-DESIGN.md`（场景路径）。
特征线三处刻意不同：① 生化线按 **"这张单子的参考上限"** 组织，不看通用区间；
② 痒与累是**独立功能线**，且与同日指标**只并列不推断**；③ 并发症筛查按**部位/系统分节**，不并入主生化趋势。

## 4. 数据与 API

见 `docs/SCHEMA.md`（M3 冻结）与 `docs/API-CONTRACT.md`。要点：
- 事实四层不合并：文档（原件）/ 候选（解析或 AI 产出）/ 记录（人工确认）/ 指标（结构化数值）。
- 判读列禁止：无 `diagnosis` / `risk_level` / `response` / `stage` 一类判定列（G3 断言）。
- 单位与参考范围随每条化验记录存储，**不继承**上一次。

## 5. 本轮明确不做

- 不做诊断、不做分期/分级判定、不做"应答/未应答"结论、不建议用药与剂量。
- 不接指南页码层（原件未取得）；不写"指南建议你…"。
- 不做家属早筛提醒（PBC 非传染性疾病，家系筛查非常规，且无原件可核）。
- 不做照护者独立身份/权限（G1 范围外）。
- 不做 AI 自动写入事实层：AI 只产候选，逐项确认。

## 6. 患者视角红线落地

每条功能线挂一句患者原话（SCENARIOS.md 逐条列出），**本轮 0 访谈，全部原话标注为"改写句/假设"**，
不得当作一手引语；拿到真实访谈后逐条替换并升版本。
